# BusiMirror：用 Multi-Agent 构建平行商业世界，让生意在 AI 群中预演

> "让生意在 Agent 群中预演，让决策在博弈后胜出。"

如果你能在投入真金白银之前，先在一个虚拟市场里"跑一遍"——让 AI 扮演的买家和卖家自由交易、博弈演化——然后拿到一份趋势预测报告，你会怎么用？

这不是思想实验。这是 **BusiMirror（生意仿真）** 正在做的事情。

---

## 一句话理解：这东西到底是什么？

传统的市场分析是**回头看**——用历史数据拟合趋势线，然后外推。

BusiMirror 是**向前模拟**——让一群 AI 智能体（Agent）在一个虚拟的 1688 分销市场里，按照真实的商业规则进行多轮交易博弈，然后观察"会发生什么"。

类比：
- 传统方法 → 看过去 100 盘棋局的胜率统计
- BusiMirror → 让两个 AlphaGo 现场对弈 100 盘，看结果

## 五步工作流：从数据到洞察

整个产品的使用体验被设计成一条极简的 5 步流水线：

### Step 1 · 数据注入
上传 PDF / Markdown / TXT 格式的行业数据和市场报告，用自然语言描述你的仿真需求。比如：

> "预测 2026 年 Q3 瑜伽垫品类在 1688 分销渠道的竞争格局变化"

系统甚至提供了内置的示例数据文件，可以一键体验。

### Step 2 · 世界构建
这一步是魔法发生的地方。系统会：
1. **提取本体**——从文档中识别出商业实体（品类、品牌、渠道、价格带）
2. **构建知识图谱**——建立实体间的关系网络
3. **生成 Agent 画像**——为每个买家/卖家创建详细的人设档案

每个 Agent 都有独特的属性：资金量、风险偏好、运营能力、内容创作水平、加价策略……这些不是随机数，而是从真实市场数据中提取并合理分布的。

### Step 3 · 仿真推演
核心环节。多个 AI Agent 在虚拟市场中开始多轮博弈。你可以**实时**看到：
- 每轮的交易帖子和动态
- Agent 的行为时间线
- 市场竞争度的演化曲线
- 各个 Agent 的资金、销量、利润统计

### Step 4 · 趋势预测
仿真结束后，`report_agent` 自动聚合分析数据，生成一份结构化的趋势预测报告。

### Step 5 · 深度互动
报告不是终点。你可以**与报告 Agent 对话**，追问任何细节：

> "为什么 Agent #3 在第 8 轮选择了退出市场？"
> "如果初始资金翻倍，竞争格局会怎么变？"

## 技术深潜：双引擎混合架构

BusiMirror 最精彩的技术设计，在于它的**"确定性基座 + 非确定性决策"**混合架构。

<img src="/images/busimirror/agent-decision-flow.svg" alt="Agent 决策循环流程" style="max-width:100%;margin:2em 0;" />

### 为什么不能全用 LLM？

一个自然的问题：既然已经在用 LLM 做决策了，为什么不让 LLM 也负责销量计算、利润结算？

答案是：**经济学基本规律不能"幻觉"。**

如果让 LLM 来算"这个商品本轮卖了多少件"，它可能会编一个听起来合理但完全错误的数字。1200 件和 120 件的差别，会让整个仿真世界崩塌。

所以 BusiMirror 做了一个经典的工程决策：

| 职责 | 谁来做 | 为什么 |
|------|--------|--------|
| 销量计算 | 数学公式 | 不能有幻觉 |
| 利润结算 | 数学公式 | 不能有误差 |
| 退货率建模 | 数学公式 + 随机噪声 | 基础规律确定，波动随机 |
| 铺货/定价/推广决策 | LLM Agent | 需要主观商业判断 |
| 退出/扩张决策 | LLM Agent | 需要人设 + 风险评估 |

这种设计，我称之为**"公式是骨架，LLM 是灵魂"**。

### 13 个核心公式：数学引擎

<img src="/images/busimirror/formula-system.svg" alt="13 个核心公式系统" style="max-width:100%;margin:2em 0;" />

让我挑几个最有意思的公式拆解：

#### 公式 ① 商品总销量——三次方爆发

```
item_total_qty = int(50 + 1200 × hot_score³)
```

为什么用三次方而不是线性？因为现实中的爆款就是这样——热度从 0.5 到 0.9 的提升，带来的销量增长远比 0.1 到 0.5 大得多。

| hot_score | 销量 | 体感 |
|-----------|------|------|
| 0.1 | 51 件 | 冷门 |
| 0.5 | 200 件 | 平稳 |
| 0.9 | 1,124 件 | 爆款 |

基础值 50 的设计也很精妙：**保证哪怕最冷门的商品也有最低出单量**，避免结算卡片为空。

#### 公式 ③ 买家销售能力——内容为王

```
capability = (0.35 × shop_efficiency + 0.65 × content_capability ^ 1.6) × promote_effect
```

注意权重分配：**内容创作能力占 65%，运营效率只占 35%**。这不是拍脑袋，而是对 1688 分销生态的精确建模——在内容电商时代，会做内容的分销商确实能吃到更多份额。

更妙的是 `content_capability ^ 1.6` 这个 1.6 次方：
- content=0.3 → 0.3^1.6 = 0.14 （内容差的人被大幅压缩）
- content=0.8 → 0.8^1.6 = 0.70 （内容好的人获得显著放大）

**这就是马太效应的数学化表达。**

#### 公式 ⑬ 处罚概率——平台监管仿真

```
penalty_prob = min(0.05 + 0.10 × price_premium_ratio + 0.05 × content_capability, 0.30)
```

三个有趣的设计点：
1. 基础处罚率 5%——任何人都有可能被抽查
2. 溢价越高，被关注概率越大——高价卖家更易触发监管
3. 内容能力越强（曝光越高），被查概率也越大——这看似反直觉，但在真实电商平台中完全成立
4. 上限 30%——不会过度惩罚，避免仿真变成"抓人游戏"

## 5 种 Agent 动作：AI 的经营武器库

每轮仿真中，每个 Agent 面对每个商品，都需要做出决策。LLM 会收到完整的市场观察数据，然后从 5 种动作中选择：

### 1. ADD_SUPPLY（铺货）
> "这个品的热度连续 5 轮上升，竞争度才 0.35，同行月销 150 件——我要入场。"

LLM 会评估：热度趋势 → 竞争程度 → 同行销量 → 品类盈亏历史 → 资金状况。

### 2. RESET_PRICE（改价）
> "连亏 3 轮了，同行的价格比我低 20% 还在出量——我得降价。"

改价不是简单的"降就对了"。LLM 需要平衡利润率和出货量的关系。

### 3. PROMOTE（推广）
> "这个品已经稳定盈利了，但销量增长停滞——投 500 块推广试试。"

推广有门槛（最低 100 元）和效果公式（对数增长，防止无脑烧钱）。

### 4. STOP_SALE（下架）
> "亏了 5 轮，热度在跌，竞争度已经 0.8 了——及时止损。"

注意：下架不会降低竞争度，反而会 +0.03。因为"退出释放了市场不好的信号，存量竞争者会更激烈地争夺剩余份额"。这个设计非常有洞见。

### 5. SHOP_SPLIT（店铺分裂）
> "我资金充裕，内容能力强，这个品还在上升期——开个分店矩阵打法。"

分裂的代价：
- 5% 资金作为分裂成本
- 剩余资金对半分
- 竞争度大幅 +0.08（对市场冲击最大）

这模拟的是真实电商中的**矩阵店铺策略**——用多个店铺吃同一个品类的份额。

## 代码架构：一图看懂调用链

```
simulation_manager（启动仿真）
  │
  └→ custom_simulation_runner（主循环）
       │
       ├→ settlement_engine_1688（Phase 1 · 结算）
       │    └→ simulation_config_1688（13 个公式函数）
       │
       ├→ prompt_generator（Phase 2 · 生成 Prompt）
       │
       ├→ openai_agent_service（Phase 2 · LLM 并行决策）
       │
       ├→ custom_simulation_runner（Phase 3 · 执行 Action）
       │
       └→ report_agent（仿真结束 · 生成报告）
            └→ report_data_tool（查询聚合数据）
```

源码地址：`1688_dataAI/business_world_simulation` 的 `fx_mvp` 分支。

前端是 Vue 3 + Vite 的 SPA，通过 Axios 调用后端 API，支持实时轮询查看仿真进度。API 超时设为 5 分钟——因为一次完整的仿真推演，可能需要 LLM 做数百次并行决策。

## 产品思考：为什么这个方向有价值？

### 1. 从"分析师思维"到"模拟器思维"

传统的市场分析报告，本质上是**一个人类分析师的单一视角**。哪怕他经验再丰富，也无法同时考虑 20 个分销商的博弈策略、50 个商品的竞争演化、市场监管的随机抽查。

Multi-Agent 仿真，是把**整个市场当作一个可计算的系统**来运行。每个参与者都有自己的理性（LLM 决策）和约束（公式规则），最终的涌现结果，往往比任何单一分析师的预测更接近真实。

### 2. "确定性 + 非确定性"的混合架构是通用模式

BusiMirror 的架构设计——公式负责确定性规则，LLM 负责主观判断——不仅适用于电商仿真。**任何需要"多角色在规则内博弈"的场景都可以复用**：

- **供应链仿真**：工厂、物流、零售商的三方博弈
- **金融市场**：多空双方的交易策略演化
- **城市规划**：居民、商户、政府的利益平衡
- **游戏 AI**：NPC 在经济系统中的自主行为

### 3. Prompt 工程的最佳实践

BusiMirror 的 Agent Prompt 设计值得专门学习：
- **System Prompt** 注入人设属性（一次性，不变）
- **User Prompt** 注入动态观察数据（每轮更新）
- **输出格式严格约束** 为 JSON（`execute / action_args / reasoning`）
- **reasoning 字段** 要求引用具体数据，不允许空泛判断

这种 "固定人设 + 动态观察 + 结构化输出" 的三层 Prompt 架构，我在很多 Agent 项目中都没有见到做得这么干净的。

## 写在最后

BusiMirror 给我的最大启发不是技术本身，而是一个产品理念：

**与其让 AI 帮你"算"答案，不如让 AI 帮你"演"未来。**

在一个由公式驱动的虚拟世界里，让一群有"灵魂"的 AI Agent 自由博弈——然后你在上帝视角观察，从中提取你需要的洞察。

这不是预测。这是预演。

而在 B2B 电商这个足够复杂、参与者足够多、规则足够明确的领域，预演的价值可能远超预测。
