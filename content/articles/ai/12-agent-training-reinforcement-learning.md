# 强化学习如何让Agent越来越聪明？从RLHF到GRPO的进化

> SFT（有监督微调）让模型学会了"照葫芦画瓢"式的工具调用。但真实世界的Agent任务充满不确定性——没有标准答案，只有"做得好不好"的反馈。这正是强化学习的主场。

---

## 为什么SFT不够？

SFT 的本质是**行为克隆（Behavior Cloning）**：给模型大量正确示范，让它学会模仿。问题在于：

1. **分布外泛化差**：遇到训练数据中没见过的工具组合或任务，模型不知道该怎么做
2. **无法从错误中学习**：SFT 只看正确示例，不教模型"做错了怎么调整"
3. **多步决策的累积误差**：每步 95% 正确，10步下来只有 60% 的整体成功率
4. **无法权衡取舍**：面对多种可行路径时，SFT 模型无法判断哪条更优

类比：SFT 像教小孩下棋只看棋谱，而 RL 像让他实际下棋、输了反思、赢了强化。

---

## RLHF：人类当教练

### 基本流程

**RLHF（Reinforcement Learning from Human Feedback）** 是最早大规模应用于 LLM 的 RL 方法：

```
1. 模型生成多个候选回答（或多条工具调用路径）
2. 人类标注员对候选进行排序/打分
3. 用排序数据训练一个奖励模型（Reward Model）
4. 用 PPO 算法，以奖励模型的打分为信号优化策略模型
```

### PPO（Proximal Policy Optimization）

PPO 是 OpenAI 最早在 ChatGPT 中使用的 RL 算法。核心思想：

- **策略模型**：正在被训练的 LLM
- **奖励模型**：预测人类偏好的打分器
- **参考模型**：冻结的旧版本，防止策略偏离太远（KL 散度约束）
- **价值模型**：估计未来累积奖励的 baseline

PPO 更新公式（简化版）：
```
loss = -min(ratio * advantage, clip(ratio, 1-ε, 1+ε) * advantage)
```

### RLHF 在 Agent 场景的局限

| 局限 | 原因 |
|------|------|
| 成本极高 | Agent任务需要标注完整的多步执行轨迹，单个样本标注可能需要30分钟 |
| 标注一致性差 | 不同标注员对"好的Agent行为"判断不同 |
| 延迟反馈 | Agent任务的好坏往往只有在全部执行完才知道 |
| 奖励稀疏 | 20步中只有最后一步有明确的成功/失败信号 |

## RLAIF：AI当教练

### 核心思想

**RLAIF（RL from AI Feedback）** 用一个强大的 AI 模型替代人类标注员提供反馈。Anthropic 的 Constitutional AI 是这个方向的代表：

```
1. 定义一组评估原则（"宪法"）
2. Agent 执行任务生成轨迹
3. Critic 模型根据原则评估轨迹质量
4. 用评估结果作为奖励信号训练 Agent
```

### 在 Agent 场景的评估维度

```json
{
  "task_completion": "任务是否完成？(0-1)",
  "tool_accuracy": "工具调用参数是否正确？(0-1)",
  "efficiency": "是否用了最少的步骤？(0-1)",
  "safety": "是否有不安全的操作？(0-1)",
  "reasoning_quality": "推理过程是否合理？(0-1)"
}
```

### 优势

- 成本降低 10-100 倍（无需人工标注）
- 可以大规模并行评估
- 评估标准一致性高
- 可以针对 Agent 特有维度（如工具选择合理性）设计细粒度评估

---

## RLEF：环境当教练

### 核心思想

**RLEF（RL from Environment Feedback）** 直接用环境的真实反馈作为奖励信号——这是 Agent 训练中最自然的方式：

```
Agent写代码 → 运行测试 → 测试通过 = 奖励+1
Agent修bug → 编译 → 编译失败 = 奖励-1
Agent搜索 → 返回结果 → 用户确认相关 = 奖励+0.5
```

### 为什么 RLEF 特别适合 Agent？

1. **奖励信号真实**：不依赖人类判断或AI评估，是任务本身的客观反馈
2. **可自动化**：大量任务（编程、数据分析）可以自动验证结果
3. **覆盖面广**：可以在数千个任务上并行训练
4. **无标注成本**：环境反馈免费

### 典型训练环境

| 环境 | 任务类型 | 奖励信号 |
|------|---------|---------|
| SWE-bench | 代码修复 | 测试是否通过 |
| WebArena | Web操作 | 页面状态是否符合目标 |
| OSWorld | 桌面操作 | 任务是否完成 |
| 代码沙箱 | 代码生成 | 编译+运行+输出正确 |
| API Mock | 工具调用 | 返回值是否符合预期 |

## GRPO：DeepSeek 的效率突破

### PPO 的痛点

PPO 需要同时维护 4 个模型（策略、奖励、参考、价值），训练开销巨大：
- GPU 内存占用是 SFT 的 4 倍
- 训练稳定性差，超参数敏感
- 价值模型的估计误差会传导到策略更新

### GRPO（Group Relative Policy Optimization）

DeepSeek 在 R1 论文中提出的 GRPO 直接砍掉了价值模型，用**组内相对排序**替代绝对奖励估计：

```
对同一个问题，让模型生成 G 个候选回答（一组）
对组内所有回答计算奖励 r1, r2, ..., rG
计算组内均值 μ 和标准差 σ
归一化优势：Ai = (ri - μ) / σ
用归一化优势更新策略（好于平均的强化，差于平均的抑制）
```

### 关键优势

| 对比维度 | PPO | GRPO |
|---------|-----|------|
| 需要的模型数 | 4（策略+奖励+参考+价值） | 2（策略+参考） |
| GPU内存 | 4x baseline | 2x baseline |
| 训练效率 | baseline | 提升 30-50% |
| 超参数敏感度 | 高（容易崩） | 低（更稳定） |
| 适用场景 | 通用 | 特别适合有明确奖励信号的场景 |

### 为什么 GRPO 特别适合 Agent 训练？

Agent 任务通常有**明确的成功/失败信号**（代码跑通、测试通过、任务完成），这意味着不需要复杂的价值估计——直接比较"谁做得好"就够了。

## PRM：过程奖励模型

### ORM vs PRM

- **ORM（Outcome Reward Model）**：只看最终结果打分。"代码通过测试 = +1，失败 = -1"
- **PRM（Process Reward Model）**：对推理过程的每一步打分。"第1步分析正确 +0.1，第2步工具选择正确 +0.1，第3步参数错误 -0.2..."

### 为什么 Agent 需要 PRM？

20步的 Agent 任务中，如果只给最终奖励：
- 模型不知道哪一步做对了、哪一步做错了
- 正确的前10步和错误的第11步得到一样的惩罚
- **credit assignment（功劳分配）** 问题严重

PRM 解决这个问题：

```
Step 1: read_file("bug.py")          → score: +0.8 (正确的第一步)
Step 2: grep("error_handler")        → score: +0.6 (合理的调查方向)
Step 3: edit_file("bug.py", wrong_fix) → score: -0.5 (修改逻辑错误)
Step 4: run_tests()                  → score: +0.3 (验证意识好)
Step 5: edit_file("bug.py", correct_fix) → score: +0.9 (纠正了错误)
```

### PRM 的训练

PRM 本身也需要训练数据。来源：
1. **人工标注**：标注员逐步判断推理过程的正确性（OpenAI 的做法，成本高）
2. **蒙特卡洛估计**：从某一步开始多次采样，统计最终成功率作为该步骤的价值估计
3. **自动验证**：利用编译器、测试框架等自动判断中间步骤的正确性

## Rejection Sampling + SFT：轻量级替代方案

不是所有团队都有资源跑完整的 RL 流程。**Rejection Sampling**是一种折中方案：

```
1. 对同一个任务，让模型生成 N 个候选轨迹
2. 用环境反馈筛选出成功的轨迹
3. 用成功轨迹做 SFT（相当于"只学习做对的"）
4. 重复迭代
```

这本质上是 RL 的简化版——没有梯度层面的策略优化，但通过迭代筛选也能持续提升。DeepSeek V3 的早期 Agent 训练使用了这种方法。

## 各方法对比总结

| 方法 | 奖励来源 | 训练成本 | Agent适用性 | 代表 |
|------|---------|---------|------------|------|
| RLHF | 人类标注 | 极高 | 中（标注瓶颈） | ChatGPT |
| RLAIF | AI评估 | 中 | 高（可细粒度评估） | Claude |
| RLEF | 环境反馈 | 低 | 极高（天然适配） | 编程Agent |
| GRPO | 组内相对排序 | 中低 | 极高（高效） | DeepSeek R1/V4 |
| PRM | 过程监督 | 高 | 极高（解决稀疏奖励） | OpenAI o系列 |
| Rejection Sampling | 环境筛选 | 低 | 中（迭代慢） | 早期方案 |

## 实际训练中的组合策略

真实的 Agent 训练不会只用一种方法，而是**多种方法的流水线组合**：

```
阶段1: SFT
  → 大量合成数据教会基本的工具调用格式

阶段2: Rejection Sampling + SFT  
  → 在真实任务上筛选成功轨迹，强化正确模式

阶段3: GRPO/PPO + RLEF
  → 在环境中自主探索，用真实反馈优化策略

阶段4: PRM + 推理时间搜索
  → 训练过程奖励模型，推理时用它引导最优路径
```

DeepSeek V4 的 Agent 训练大致遵循这个范式，在 V3.1 阶段引入专项 Agent RL 训练，到 V4 进一步深化。
